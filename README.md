## 📖 Overview

**Network Honeypot** listens on fake **SSH, FTP, Telnet and HTTP** ports, presents believable service banners, and silently records every connection, login attempt and payload sent by a remote client. All activity is written to a human-readable log and a machine-friendly JSON Lines file, ready for analysis, threat-intel enrichment or SIEM ingestion.

> 🔒 **It NEVER executes anything the attacker sends.** All received data is sanitised and only logged.

## ✨ Features

- 🎭 **Four emulated services:** SSH, FTP, Telnet and HTTP, each with a realistic banner
- 🔑 **Credential capture:** usernames and passwords from FTP and Telnet login attempts
- 🌐 **HTTP request logging:** request line, headers, `User-Agent` and POST body, served with a fake "Router Login" page
- 🧾 **Dual logging:** plain text (`honeypot.log`) and structured JSON Lines (`events.jsonl`)
- 🧵 **Multi-threaded:** one listener per port, one thread per connection
- 🛡️ **Built-in safety limits:** byte cap per connection, inactivity timeout and a global concurrency limit
- 🧼 **Output sanitisation:** non-printable attacker bytes are replaced and long values truncated before logging
- 📦 **Zero dependencies:** uses only the Python standard library

## 🧩 Emulated Services

| Service | Default Port | Standard Port | Banner / Behaviour |
|---------|:-----------:|:-------------:|--------------------|
| SSH     | `2222` | `22` | Sends an OpenSSH 7.4p1 (Debian) banner and logs the client's banner |
| FTP     | `2121` | `21` | vsftpd 3.0.3 greeting; captures `USER`/`PASS`, always replies `530 Login incorrect` |
| Telnet  | `2323` | `23` | Ubuntu 18.04.6 LTS prompt; 3 login attempts per connection, then disconnect |
| HTTP    | `8080` | `80` | Apache 2.4.29 (Ubuntu) with a fake admin login page; logs full requests |

Ports outside this list default to the **Telnet** profile.

## 💻 Usage

```bash
# Default safe (unprivileged) ports: 2222, 2121, 2323, 8080
python3 honeypot.py

# Real service ports (requires root / administrator)
sudo python3 honeypot.py --ports 22,21,23,80

# Custom bind address and log directory
python3 honeypot.py --host 0.0.0.0 --log-dir ./logs
```

### Command-line options

| Option | Default | Description |
|--------|---------|-------------|
| `--host`    | `0.0.0.0` | Interface address to bind |
| `--ports`   | `2222,2121,2323,8080` | Comma-separated list of ports to listen on |
| `--log-dir` | `honeypot_logs` | Directory where log files are stored |

Press **Ctrl+C** to stop the honeypot gracefully.

## 🗂️ Log Files

Logs are created inside the log directory (default `honeypot_logs/`):

| File | Format | Purpose |
|------|--------|---------|
| `honeypot.log`  | Plain text | Easy live monitoring (`tail -f`) |
| `events.jsonl`  | JSON Lines | Parsing, analytics, SIEM import |

### Event types

`connect` · `data` · `login` · `command` · `request` · `error` · `disconnect`

### Example: text log

```
[2026-11-09T10:21:45.123456+00:00] LOGIN      203.0.113.7:51234 -> telnet/2323  username='admin' password='123456'
```

### Example: JSON event

```json
{
  "time": "2026-11-09T10:21:45.123456+00:00",
  "event": "login",
  "src_ip": "203.0.113.7",
  "src_port": 51234,
  "service": "telnet",
  "dst_port": 2323,
  "username": "admin",
  "password": "123456"
}
```

### Quick analysis ideas

```bash
# Top attacking IPs
jq -r '.src_ip' honeypot_logs/events.jsonl | sort | uniq -c | sort -rn | head

# Most common passwords tried
jq -r 'select(.event=="login") | .password' honeypot_logs/events.jsonl | sort | uniq -c | sort -rn | head
```

## 🔧 Safety Limits

Defined at the top of `honeypot.py` and easy to tune:

| Constant | Default | Meaning |
|----------|:------:|---------|
| `MAX_BYTES_PER_CONN` | `4096` | Maximum bytes read from a single connection |
| `CONN_TIMEOUT`       | `15`   | Seconds of inactivity before the connection is closed |
| `MAX_CONCURRENT`     | `100`  | Global limit of simultaneous connections |

## 🛡️ Deployment Tips

- Run inside a **VM, container or isolated VLAN**, never on a production host.
- Use an **unprivileged user** with the default high ports and redirect real ports with firewall rules if needed.
- Do not store the honeypot logs on the same machine long-term; forward them to a safe location.
- Rotate or archive logs regularly (`logrotate` or a cron job).
